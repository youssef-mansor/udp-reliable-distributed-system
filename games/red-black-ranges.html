Ordering comes from comparing keys with <: smaller keys go left, larger keys go right, at every node. Each node is a separate heap allocation (roughly 48 bytes plus your key and value), so a map is less cache-friendly than a vector. That's the price of cheap sorted inserts and erases. Compare: std::unordered_map is O(1) on average but has no order; a sorted std::vector searches in O(log n) but inserts and erases in O(n).

The rules

A seq is new only if it is > contiguous and not inside a stored range. Deliver new seqs only, or PL2 breaks.

Store the new run as one range, merging with any range it overlaps or touches.

If the smallest range now starts at contiguous + 1, absorb it: contiguous jumps to its end.
